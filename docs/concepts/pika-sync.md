# pika sync — Protected Areas Reference

`pika sync` updates your consumer repo with the latest pika framework files. To prevent your customisations from being overwritten or deleted, pika maintains a **protected areas** list — paths that sync will never touch.

## How protected areas work

1. **Default protected areas** ship with pika and are stored in `packages/pika-cli/src/config/protected-areas.json`. They are pushed to your consumer's `.pika-sync.json` automatically on every sync so you always have the current list.
2. **User-defined protected areas** can be added in your `.pika-sync.json` under `userProtectedAreas`. These are merged with the defaults.
3. **User-unprotected areas** (`userUnprotectedAreas`) let you opt specific paths back into syncing even if they appear in the default list.

## Default protected paths (v0.26.0 / protected-areas.json v1.0.5)

### Consumer extension globs

| Path | Why it is protected |
|------|---------------------|
| `apps/pika-chat/src/lib/custom/**` | Primary extension point — all consumer-specific logic lives here |
| `apps/pika-chat/static/custom/**` | Consumer static assets |
| `apps/pika-chat/src/lib/client/features/chat/markdown-message-renderer/custom-markdown-tag-components/**` | Custom markdown components |
| `apps/pika-chat/src/lib/server/auth-provider/**` | Auth provider implementation (OIDC, AzureAD, etc.) |
| `services/custom/**` | Consumer-specific services |
| `apps/custom/**` | Consumer-specific apps |

### Account / entity integration extension points (ES-3129)

| Path | Why it is protected |
|------|---------------------|
| `apps/pika-chat/src/lib/custom-shared-types.ts` | Consumer domain types (`AccountLite`, `DscoAuthData`, etc.) referenced by other custom files; deleting it breaks the build |
| `apps/pika-chat/src/lib/server/custom-site-features.ts` | Generated by `site-features-vite-plugin`; contains consumer-specific site config. "Do not change this file" in JSDoc but it must persist across syncs |
| `apps/pika-chat/src/routes/(auth)/api/session/legacy/[chatAppId]/+server.ts` | Consumer legacy-session endpoint (e.g. DSCO tools integration) |
| `apps/pika-chat/src/routes/(auth)/api/user-data-override/custom-account-search-api.ts` | Consumer account-service integration |
| `apps/pika-chat/src/routes/(noauth)/auth/callback/azuread/+server.ts` | Consumer AzureAD auth-provider callback; companion to the protected `lib/server/auth-provider/**` |
| `apps/pika-chat/tools/custom-*/**` | Consumer dev tooling subdirectories (e.g. `custom-ssl/`, `custom-update-all-users/`) |

### Auth routes (framework-scaffolded but consumer-owned)

| Path | Why it is protected |
|------|---------------------|
| `apps/pika-chat/src/routes/(noauth)/auth/client-auth/+page.server.ts` | Consumer-side client-auth page logic |
| `apps/pika-chat/src/routes/(noauth)/auth/client-auth/+page.svelte` | Consumer-side client-auth page UI |
| `apps/pika-chat/src/routes/(noauth)/logout/+page.svelte` | Consumer logout page |

### Consumer configuration files

| Path | Why it is protected |
|------|---------------------|
| `.env`, `.env.local`, `.env*` | Environment variables |
| `pika-config.ts` | Consumer pika configuration |
| `.pika-sync.json` | Sync state and consumer-defined protected areas |
| `.gitignore` | Consumer gitignore |
| `package.json` | Consumer package manifest |
| `pnpm-lock.yaml` | Lockfile |
| `cdk.context.json` | CDK context cache |

### CI/CD pipelines

All common CI/CD config files and directories are protected: `.github/**`, `.gitlab/**`, `.circleci/**`, `.bitbucket/**`, `.azure-pipelines/**`, `.azure/**`, `.ci/**`, and their corresponding root-level config files.

### Documentation and tooling

| Path | Why it is protected |
|------|---------------------|
| `README.md`, `readme.md`, `README-pika.md` | Consumer documentation |
| `CODEOWNERS`, `CONTRIBUTING.md`, `AGENTS.md` | Consumer repo governance |
| `RELEASING.md`, `releases.json`, `RELEASE-SYSTEM-SUMMARY.md` | Consumer release tracking |
| `packages/tools/**` | Consumer release tooling |
| `Makefile`, `Jenkinsfile`, `buildspec.yml`, etc. | Build tooling |

## Migration note for v0.26.0

If you previously added any of the **ES-3129** paths to your own `userProtectedAreas` in `.pika-sync.json`, you can safely remove them — they are now covered by the default list and will be pushed to your repo on next sync.

Affected paths:
- `apps/pika-chat/src/lib/custom-shared-types.ts`
- `apps/pika-chat/src/lib/server/custom-site-features.ts`
- `apps/pika-chat/src/routes/(auth)/api/session/legacy/[chatAppId]/+server.ts`
- `apps/pika-chat/src/routes/(auth)/api/user-data-override/custom-account-search-api.ts`
- `apps/pika-chat/src/routes/(noauth)/auth/callback/azuread/+server.ts`
- `apps/pika-chat/tools/custom-*/**`

## Adding a new protected path

1. Add the path to `packages/pika-cli/src/config/protected-areas.json` and bump `"version"` + `"lastUpdated"`.
2. Mirror it in the fallback list inside `getDefaultProtectedAreas()` in `packages/pika-cli/src/commands/sync.ts`.
3. Add a row to the table above with a one-line rationale.
